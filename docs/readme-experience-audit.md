## 应优先学习的原则

1. **输入可靠**：未被接受的提交不能清空草稿；模式、项目、任务的上下文应该有明确归属。
2. **状态可信**：消息结束、工具结束和任务结束是不同事件；失败、中断和未知状态不能伪装为完成。
3. **阅读可控**：在底部阅读时跟随新增输出，上翻查阅时保留位置，提供明确的返回入口。
4. **错误可恢复**：让错误出现在用户操作的位置，保留原输入和设置，并提供重试或退出路径。
5. **细节按需展开**：回答优先，工具过程、变更、权限和来源可检查；不能用动效代替执行证据。

这些是本次从现有缺陷提炼出的设计准则，不是对其他产品内部实现的推测。

## 首次审计的优先级

下一轮应先完成 **按任务保存完整草稿**：文字、光标、附件、技能／文件／插件绑定一起保存，
并处理新任务拿到远端 ID 后的归属迁移。只按文字分桶会让附件和绑定仍然错位。

其次是 **截图权限与失败恢复**、**Conversation 附件管理** 和 **真实流式回答**。
它们分别影响首次使用、误操作撤回和等待反馈，比增加装饰性动画更直接。

其中草稿、附件与流式回答已在随后一轮落地。截图权限及失败恢复仍需独立处理；
它不属于参考仓库的现成能力。
